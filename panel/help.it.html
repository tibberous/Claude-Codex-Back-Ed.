Codex Black Ed.

Pannello AI autonomo per VSCode. Chat con qualsiasi provider LLM (API diretta o bridge browser), con TTS integrato, STT, allegamento a file, palette comandi, multi-account, skinning e un Tamagotchi pixel-pet.

Avvio rapido ↑ inizio

  1. Fai clic su Setup (icona bacchetta magica) e segui la procedura guidata per inserire le tue chiavi API. Vengono salvate in config.ini (che è gitignored — mai committato).
  2. Fai clic sulla pillola del provider in basso a sinistra (attualmente etichettata "Codex Black Ed.") per cambiare con quale AI stai parlando.
  3. Digita nella textarea e premi Invio per inviare. Maiusc+Invio inserisce una nuova riga.
  4. Premi ↑ in una textarea vuota per richiamare i prompt precedenti (cronologia in stile PowerShell).

Ogni bridge è un piccolo eseguibile C++ da vassoio in bin/CBE-Bridge-<Target>.exe che apre un profilo Chrome collegato, intercetta il tuo prompt e restituisce la risposta del modello. Selezionare un provider bridge in Impostazioni avvia automaticamente l'eseguibile corrispondente. La prima volta che usi un bridge devi accedere al sito nella sua finestra Chrome.

Bridge chat parla un protocollo di linea su TCP: una riga JSON in ({action:"chat", target, message, model}), una riga JSON out. Nessuna chiave API richiesta.

Invio messaggi ↑ inizio

Textarea
Digita il tuo prompt. Invio invia, Maiusc+Invio inserisce una nuova riga. Mentre una risposta è in streaming, i prompt aggiuntivi vengono accodati e inviati in ordine — il placeholder mostra "Accoda un altro messaggio…" durante questo stato.
Pulsante Invia (sfera)
Il pulsante rotondo al bordo destro della textarea. Uguale a Invio. Mostra visivamente tre stati (inattivo / hover / attivo).
Pulsante Stop
In basso a destra del compositore. Annulla la risposta attualmente in streaming e i messaggi accodati. Il testo già inviato viene conservato; solo la richiesta in corso è interrotta.
Pillola del provider
In basso a sinistra del compositore. Fai clic per un elenco a discesa di ogni provider che hai configurato. La selezione di uno nuovo avvia automaticamente il suo bridge (se applicabile) e pubblica un toast di conferma.
Cronologia dei prompt
↑ / ↓ in una textarea vuota naviga all'indietro / in avanti attraverso gli ultimi 500 prompt che hai inviato (stile PowerShell). La cronologia è memorizzata in prompt_history.txt nella cartella dell'estensione e persiste nei ricaricamenti del pannello.

Menu del tasto destro ↑ inizio

Fai clic con il tasto destro sul testo della chat o su un blocco di codice per ottenere il menu contestuale CBE. Fai clic con il tasto destro sulla textarea del prompt ora apre il menu del browser nativo (Copia / Taglia / Incolla / Elimina / Seleziona tutto) al contrario.

Copia / Copia blocco di codice
Copia la selezione corrente. Se non hai una selezione ma hai fatto clic con il tasto destro su <pre><code>, copia l'intero blocco di codice.
Visualizza sorgente
Mostra l'HTML/markdown grezzo della regione su cui hai fatto clic — un blocco di codice o l'intero DOM del pannello. Utile per il debug di problemi di skin/CSS.
Apri DevTools
Chiede a VSCode di aprire i suoi Strumenti per sviluppatori affinché tu possa ispezionare la webview in tempo reale.
Impostazioni new
Apre la stessa modale Impostazioni che il pulsante della barra degli strumenti Impostazioni apre (provider / modello / skin / lingua / SFX). Uguale a /settings.
Informazioni new
Piccolo dialogo nel pannello con versione, autore, licenza, link del repository, portfolio e telefono di contatto. Si chiude al clic dello sfondo, al pulsante × o a Esc.
Ricarica pannello new
Rilegge panel/index.html + panel.js + skins/* con un cache-buster per file ?v=<mtime> e ridassegna panel.webview.html. Ritira le modifiche CSS/JS senza riavviare VSCode. L'host dell'estensione rimane attivo — terminale, supervisore, cronologia della chat persiste tutto.
Ricarica finestra new
Attiva workbench.action.reloadWindow. Usa questo solo quando hai modificato extension.js (codice lato host) e il ricaricamento del pannello non è sufficiente. È un ricaricamento completo della finestra VSCode.

Modali e dialoghi ↑ inizio

Modale Impostazioni — provider / modello / skin / lingua / SFX
  • Provider: elenco a discesa completo di ogni provider API diretta + bridge. La selezione di uno cambia la sessione attiva E avvia automaticamente l'eseguibile del bridge corrispondente (se applicabile).
  • Modello: per-provider elenco di modelli consentiti (ad es. claude-opus-4-7, claude-sonnet-4-6, claude-haiku-4-5 per Anthropic).
  • Skin: tema visivo. Vedi Skin.
  • Lingua: 39 lingue disponibili. La commutazione ritira nuovamente la mappa delle stringhe e ritraduce ogni tooltip / etichetta / pulsante della guida in tempo reale.
  • SFX abilitati: attiva/disattiva gli effetti sonori dell'interfaccia utente (clic, tic, apertura/chiusura modale, ecc.).
  • Volume SFX: slider 0–100. Visualizzato in anteprima in tempo reale mentre trascini.
  • Annulla ripristina le anteprime in tempo reale (SFX/skin) che hai provato; Salva persiste e emette setProvider.
Procedura guidata di setup — immissione di chiavi API multi-step

Procedura guidata per ogni integrazione. Ogni passaggio chiede le credenziali e le scrive su config.ini. Salta avanza senza scrivere; Avanti scrive e avanza; il pulsante Fine dell'ultimo passaggio chiude. I passaggi includono: Anthropic, OpenAI, Gemini, xAI/Grok, GitHub PAT, Email/SMTP (password app Gmail), Cloudflare, Twilio, ElevenLabs, Stability AI, Runway, SendGrid, NameSilo e altro.

Modale Domini — NameSilo

Modale Prompt salvati

Modale Prompt automatico

Configura una stringa di prompt + intervallo di conto alla rovescia. Dopo ogni risposta dell'assistente il conto alla rovescia decrementa; quando raggiunge zero CBE invia automaticamente il prompt configurato. Attivato/disattivato tramite il pulsante della barra degli strumenti Prompt automatico.

Impostazioni ↑ inizio

Tutte le impostazioni si trovano in uno di due posti:

  • workspaceState (gestito da VSCode, per workspace) — provider, modello, skin, lingua, SFX abilitati/volume, dimensione carattere.
  • config.ini (radice dell'estensione, gitignored) — chiavi API + credenziali per integrazione.

Le impostazioni persiste nei ricaricamenti del pannello automaticamente. La modale Impostazioni è il modo sicuro per cambiare qualunque cosa; la modifica diretta di config.ini funziona anche.

Account e chiavi API ↑ inizio

Ogni provider può avere più account etichettati — utile se desideri cambiare tra chiavi personali e di lavoro o testare un livello diverso. La modale Account ti consente di:

  • Aggiungere un nuovo account con un'etichetta + chiave
  • Modificare un account esistente (rietichetta, sostituisci la chiave)
  • Imposta quale account sia attivo per la sessione corrente
  • Rimuovere un account

Le chiavi vengono memorizzate mascherate (visibili solo gli ultimi quattro) in config.ini. Non c'è nessuna copia in testo semplice in workspaceState.

Tamagotchi pet ↑ inizio

Il Tamagotchi è un pixel-art pet che vive nel pannello sotto la skin tamagotchi. Invecchia, ha fame/è sporco, può essere giocato con, e muore se trascurato abbastanza a lungo. Lo stato persiste in workspaceState.

StatisticaCosa traccia
🥚 FaseCiclo di vita: uovo → bambino → bambino → adolescente → adulto → anziano → morto. Invecchia con minuti in tempo reale.
🍖 Fame0–100. Scende nel tempo; Nutri lo aumenta. Raggiunge 0 → salute scende.

Skin ↑ inizio

Temi visivi per l'intero pannello — pulsanti, modali, blocchi di codice, anche carattere. Scegline uno in Impostazioni → Skin. Ogni skin si trova in skins/<id>/ con manifest.xml (dichiara colori + accento) e styles.css (sostituisce le variabili CSS).

  • codex-black (predefinito) — scuro, monospace, accento ciano neon
  • glassy — superfici di vetro smerigliato su uno sfondo morbido
  • tamagotchi — handheld LCD verde lime; mostra automaticamente il widget del pet ancorato all'angolo del compositore
  • office — stile Word crema/blu chrome
  • macos-color-dock / mint-dock — barre degli strumenti bottom-dock con icone glassy
  • terminal / arch / kde / gnome / xfce / ubuntu / redhat — Temi desktop Linux

I colori della modale provengono dalle voci <colors> nel manifest di ogni skin e vengono inseriti su :root come variabili --cbe-modal-* in modo che ogni modale (incluso questo aiuto) venga renderizzata in tema.

Estensioni ↑ inizio

Mini-app che vivono dentro CBE. Ognuno è una cartella in extensions/<id>/ con:

  • manifest.xml — id, nome, versione, autore, descrizione, HTML entry, icona (emoji o icon.svg)
  • extension.html (o qualunque il manifest's <entry> dice) — l'app effettiva

Fai clic su Estensioni per sfogliare cosa è installato, fissa alla barra degli strumenti, installa quelle nuove dal catalogo pubblico o rimuovi dal disco. Gli ID fissati si trovano in extensions/_pinned.json.

Aggiornamento automatico (push / pull) ↑ inizio

CBE sincronizza il suo sorgente tra le macchine tramite un canale push WinSCP + pull HTTPS.

Push (solo admin)

Se [updates] is_admin = true in config.ini, ogni attivazione esegue uno WinSCP synchronize remote -mirror in background che invia la cartella dell'estensione a /home/trentontompkins.com/cbe sul server. Trigger manuale: comando slash /push. Esclude lo stato per macchina: data/ (profili Chrome 1,74 GB), bridges/, node_modules/, .git/, logs/, chats/, config.ini, prompt_history.txt, domains.txt, wake.txt.

Pull (ogni client)

4 secondi dopo l'attivazione, ogni client recupera https://trentontompkins.com/cbe/manifest.xml.php e MD5-confronta per file rispetto alle copie locali. Solo i file modificati/mancanti vengono scaricati su HTTP GET semplice. I percorsi esclusi NON vengono mai recuperati: config.ini, data/, bridges/, extension.js, panel/panel.js, panel/index.html, package.json, strumenti di build — la ragione è che il sorgente si spedisce tramite .vsix e la copia più vecchia del server non deve sopprimere il lavoro di sviluppo in corso.

Ricaricamento veloce ↑ inizio

Due percorsi di ricaricamento sono esposti tramite il menu del tasto destro:

  • Ricarica pannello — rilegge panel/index.html + ogni risorsa JS/CSS con un cache-buster per file ?v=<mtime> e ridassegna panel.webview.html. Ritira le modifiche panel.js / skin CSS / dotmatrix senza riavviare VSCode. L'host dell'estensione rimane attivo (il tuo terminale, supervisore, gestori di messaggi, cronologia della chat persistono tutti).
  • Ricarica finestra — attiva workbench.action.reloadWindow. Usa solo quando hai modificato extension.js (codice lato host) e Ricarica pannello non è sufficiente.

Le modifiche CSS della skin si applicano anche automaticamente tramite il watcher della skin esistente del pannello — nessun clic di menu necessario.

Risoluzione dei problemi ↑ inizio

"bridge X chat failed: api key empty in config.ini"

Il daemon smart_bridge.py stava memorizzando nella cache un vecchio controllo di cancello in memoria. Corretto nel pivot di routing dell'eseguibile C++. Se lo vedi ancora, uccidi i daemon stantii:

powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*smart_bridge.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
"copilot has no public REST API — use the browser bridge"

L'estensione.js vecchia stava instradando la chat del bridge tramite il router REST al posto dell'eseguibile del vassoio C++ effettivo. Ricarica finestra per ritirare l'estensione.js corretta, quindi la chat andrà direttamente a bin/CBE-Bridge-Copilot.exe.

HTTP 404 model: sonnet-4.6

Alias breve obsoleto nella configurazione del bridge Claude. Corretto — ora vengono utilizzati i full ID (claude-sonnet-4-6, claude-opus-4-7, claude-haiku-4-5).

Ho modificato un file ma il pannello non mostra la modifica
  1. Se è panel.js / skins/*.css / index.html → tasto destro → Ricarica pannello.
  2. Se è extension.js / bridges_cpp/*.py → tasto destro → Ricarica finestra.
  3. Se non puoi raggiungere il menu (ad es. il menu stesso non è ancora caricato), avvia una nuova istanza di VSCode con una directory di dati utente isolata:
    code --user-data-dir="$env:USERPROFILE\.cbe-edh" --extensionDevelopmentPath="C:\Users\moren\Desktop\Codex Black"
STT fallisce con "not-allowed"

VSCode mette in sandbox la webview dall'autorizzazione del microfono. CBE ritorna automaticamente a Windows SAPI (System.Speech.Recognition) lanciato tramite PowerShell. Potresti avere bisogno di concedere accesso al microfono a livello del sistema operativo (Impostazioni → Privacy → Microfono).

Eseguibile Bridge mancante

Il log di traccia mostra BRIDGE:MISSING target=<t> expected=<path>. Gli eseguibili del vassoio C++ si trovano in bin/CBE-Bridge-<Pretty>.exe. Se i tuoi non esistono, ricompila dai sorgenti bridges_cpp/ (MSVC) o ritira un .vsix fresco.
