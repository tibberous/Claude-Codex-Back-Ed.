Început rapid ↑ sus

  1. Faceți clic pe Setup (pictograma baghetă magică) și urmați asistentul pentru a introduce cheile dumneavoastră API. Acestea se salvează în config.ini (care este ignorat de git — niciodată comis).
  2. Faceți clic pe pila furnizorului în partea de jos-stânga (etichetată în prezent „Codex Black Ed.") pentru a comuta cu care AI discutați.
  3. Introduceți text în zonă de text și apăsați Enter pentru a trimite. Shift+Enter inserează o linie nouă.
  4. Apăsați ↑ într-o zonă de text goală pentru a recupera instrucțiunile anterioare (istoricul în stil PowerShell).

Fiecare bridge este un mic executabil C++ din tray la bin/CBE-Bridge-<Target>.exe care deschide un profil Chrome conectat, interceptează instrucțiunea dumneavoastră și returnează răspunsul modelului. Selectarea unui furnizor bridge în Setări lansează automat executabilul potrivit. Prima dată când folosiți un bridge, trebuie să vă conectați la site în fereastra sa Chrome.

Bridge chat vorbește un protocol cu linie în TCP: o linie JSON în ({action:"chat", target, message, model}), o linie JSON în afară. Nicio cheie api necesară.

Trimiterea mesajelor ↑ sus

Zonă de text
Introduceți instrucțiunea. Enter trimite, Shift+Enter inserează o linie nouă. În timp ce un răspuns se transmite în flux, instrucțiunile suplimentare sunt puse în coadă și trimise în ordine — substituția arată „Puneți în coadă alt mesaj…" în această stare.
Buton Trimite (sferă)
Butonul rotund la marginea dreaptă a zonei de text. La fel ca Enter. Arată vizual trei stări (inactiv / plutire / activ).
Buton Stop
Jos-dreapta din compozitor. Anulează răspunsul în flux curent și orice mesaje puse în coadă. Textul transmis este păstrat; doar cererea în zbor este abortată.
Pilă furnizor
Jos-stânga din compozitor. Faceți clic pentru o listă derulantă a fiecărui furnizor pe care l-ați configurat. Selectarea unui nou pornește automat bridge-ul său (dacă este cazul) și postează o notificare de confirmare.
Istoricul instrucțiunilor
↑ / ↓ într-o zonă de text goală merge înapoi / înainte prin ultimele 500 de instrucțiuni pe care le-ați trimis (stil PowerShell). Istoricul se stochează la prompt_history.txt în dosarul extensiei și persista la reîncărcări ale panoului.

Moduri și dialoguri ↑ sus

Modă de setări — furnizor / model / temă / limbă / SFX
  • Furnizor: lista derulantă completă a fiecărui furnizor API direct + bridge. Selectarea unuia comută sesiunea activă ȘI lansează automat executabilul bridge potrivit (dacă este cazul).
  • Model: per-furnizor listă de modele permise (ex. claude-opus-4-7, claude-sonnet-4-6, claude-haiku-4-5 pentru Anthropic).
  • Temă: tema vizuală. Vezi Teme grafice.
  • Limbă: 39 de locări disponibile. Schimbarea retrage harta de șiruri și retraduce fiecare sfat / etichetă / buton de ajutor în direct.
  • SFX activat: comutați efectele sonore UI (clicuri, ticsuri, deschidere/închidere modă, etc.).
  • Volum SFX: slider 0–100. Previzualizat în direct pe măsură ce trageți.
  • Anulare revine la orice previzualizări în direct (SFX/temă) pe care le-ați încercat; Salvare persista și emite setProvider.
Asistent de configurare — intrare cheie API în mai mulți pași

Ghidaj prin fiecare integrare. Fiecare pas cere credențiale și le scrie la config.ini. Sări peste se mișcă fără scriere; pasul final Gata se închide. Pașii includ: Anthropic, OpenAI, Gemini, xAI/Grok, PAT GitHub, Email/SMTP (parolă aplicație Gmail), Cloudflare, Twilio, ElevenLabs, Stability AI, Runway, SendGrid, NameSilo și mai mulți.

Modă de conturi — manager de chei API cu conturi multiple

Pentru fiecare furnizor, gestionați multiple conturi etichetate (ex. „personal", „de lucru"). Comutați care este activ per-sesiune fără a suprascrie pe ceilalți. Cheile sunt mascate end-to-end și salvate per-furnizor în config.ini.

Modă de domenii — NameSilo

Listează fiecare domeniu din contul NameSilo cu servere de nume + date de înregistrare. Butonul Reîncărcare forțează o captură proaspătă API (altfel cache-ază în domains.txt).

Modă manual

Randează un HTML manual de proiect (destinat ca referință de instrucțiune sistemică pe care modelul o poate consulta). Configurable per-proiect.

Modă de instrucțiuni stocate

Șabloane de instrucțiuni inserabile din stored_prompts/. Fiecare fișier este un șablon; prefixul numelui de fișier NN- controlează ordinea de sortare. Butonul „+" creează unu nou.

Modă de istoricul chat

Selectați o dată UTC pentru a încărca jurnalul de chat din chats/<date>.log. Doar citire.

Modă de extensii

Cărți pentru fiecare extensie instalată. Fixați la bara de instrumente / anulați fixarea, instalați din catalogul public (extensions.xml.php pe server) sau eliminați de pe disc.

Modă jurnal de schimbări

Randează panel/change_log.html — notele de lansare incluse. Generat prin tools/build_changelog.py.

Modă vizualizare sursă

Imprimă frumos orice bloc de cod sau HTML-ul panoului întreg, cu evidențiere sintaxă Prism și un buton de copiere. Accesibil prin clic dreapta → Vizualizare sursă.

Modă instrucțiune automată

Configurați un șir de instrucțiune + interval de numărare inversă. După fiecare răspuns asistent numărarea inversă se decrementează; când ajunge la zero CBE trimite automat instrucțiunea configurată. Comutată pornire/oprire prin butonul Instrucțiune automată din bara de instrumente.

Setări ↑ sus

Toate setările trăiesc într-un din două locuri:

  • workspaceState (gestionat de VSCode, per-workspace) — furnizor, model, temă, limbă, sfx activat/volum, dimensiune font.
  • config.ini (rădăcina extensiei, ignorat de git) — chei API + credențiale per-integrare.

Setările persista pe reîncărcări ale panoului automat. Modul Setări este modul sigur pentru a schimba orice; editarea config.ini direct funcționează și ea.

Conturi și chei API ↑ sus

Fiecare furnizor poate avea multiple conturi etichetate — util dacă doriți să comutați între chei personale și de lucru sau să testați un nivel diferit. Modul Conturi permite:

  • Adăugați un cont nou cu etichetă + cheie
  • Editați un cont existent (reeticheta, înlocuiți cheia)
  • Setați care cont este activ pentru sesiunea curentă
  • Eliminați un cont

Cheile sunt stocate mascate (vizibil doar ultimele patru) în config.ini. Nu există copie în text clar în workspaceState.

Teme grafice ↑ sus

Teme vizuale pentru întregul panou — butoane, moduri, blocuri de cod, chiar și font. Selectați unu în Setări → Temă. Fiecare temă trăiește în skins/<id>/ cu un manifest.xml (declară culori + accent) și un styles.css (suprascriere variabile CSS).

  • codex-black (implicit) — întunecat, monospațiu, accent cyan neon
  • glassy — suprafețe sticlă înghetată pe o scenă moale
  • tamagotchi — aparat de mână LCD verde lime; auto-arată widgetul mascotă încadrat în colțul compozitorului
  • office — stil Word crem/albastru chrome
  • macos-color-dock / mint-dock — bare dock de jos cu pictograme sticloase
  • terminal / arch / kde / gnome / xfce / ubuntu / redhat — teme desktop Linux

Culorile modale provin din intrări <colors> din manifestul fiecărei teme și se împing la :root ca variabile --cbe-modal-* deci fiecare modă (inclusiv acest ajutor) se randează în temă.

Extensii ↑ sus

Mini-aplicații care trăiesc în CBE. Fiecare este un dosar sub extensions/<id>/ cu:

  • manifest.xml — id, nume, versiune, autor, descriere, HTML de intrare, pictogramă (emoji sau icon.svg)
  • extension.html (sau orice spune <entry> al manifestului) — aplicația efectivă

Faceți clic Extensii pentru a răsfoii ce este instalat, fixați la bara de instrumente, instalați celeनi noi din catalogul public sau eliminați de pe disc. ID-uri fixate trăiesc în extensions/_pinned.json.

Actualizare automată (push / pull) ↑ sus

CBE sincronizează sursă între mașini printr-un canal WinSCP push + HTTPS pull.

Push (doar admin)

Dacă [updates] is_admin = true în config.ini, fiecare activare execută un WinSCP synchronize remote -mirror de fundal care împinge dosarul extensiei la /home/trentontompkins.com/cbe pe server. Declanșare manuală: /push comandă slash. Exclude stare per-mașină: data/ (1,74 GB profiluri Chrome), bridges/, node_modules/, .git/, logs/, chats/, config.ini, prompt_history.txt, domains.txt, wake.txt.

Pull (fiecare client)

4 secunde după activare, fiecare client captează https://trentontompkins.com/cbe/manifest.xml.php și MD5-compară per-fișier împotriva copiilor locale. Doar fișierele modificate/lipsă sunt descărcate peste HTTP GET simplu. Căile excluse NU sunt niciodată trase: config.ini, data/, bridges/, extension.js, panel/panel.js, panel/index.html, package.json, instrumente de construire — rațiunea fiind că sursă se expediază prin .vsix și copia mai veche a serverului nu trebuie să clobbereze lucru în desfășurare.

Reîncărcare în viu ↑ sus

Două căi de reîncărcare sunt expuse prin meniu contextual:

  • Reîncărcare panou — recitește panel/index.html + fiecare activ JS/CSS cu un buster de cache ?v=<mtime> per-fișier și reatribuie panel.webview.html. Recunoaște edițiile panel.js / temă CSS / dotmatrix fără a relansa VSCode. Gazda extensiei rămâne vie (terminalul, supraveghetorul, gestionarii de mesaje, istoricul chat toate persista).
  • Reîncărcare fereastră — declanșează workbench.action.reloadWindow. Utilizați doar atunci când ați editat extension.js (cod pe partea gazdă) și reîncărcarea panoului nu este suficientă.

Edițiile CSS ale temei se aplică și automat prin ceasul temei existent al panoului — nici un clic de meniu necesar.

Depanare ↑ sus

„bridge X chat a eșuat: api key gol în config.ini"

Demonul smart_bridge.py a cache-at o verificare veche în memorie. Reparat în pivotul de rutare exe C++. Dacă încă o vedeți, omorâți demonii vechi:

powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*smart_bridge.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
„copilot nu are API REST public — folosiți bridge-ul browser"

Vechiul extension.js a rutează chat bridge prin rutele REST în loc de exe-ul C++ tray efectiv. Reîncarcă fereastră pentru a selecta extension.js reparat, apoi chat merge direct la bin/CBE-Bridge-Copilot.exe.

  3. Dacă nu puteți atinge meniul (ex. meniu însuși nu este încărcat încă), lansați o instanță VSCode proaspătă cu o user-data-dir izolată:
    code --user-data-dir="$env:USERPROFILE\.cbe-edh" --extensionDevelopmentPath="C:\Users\moren\Desktop\Codex Black"
STT eșuează cu „not-allowed"

VSCode sandbox-ează webview-ul de permisiunea microfon. CBE cad automat la Windows SAPI (System.Speech.Recognition) lansat prin PowerShell. Poate trebuie să acordați acces mic la nivel OS (Setări → Confidențialitate → Microfon).

Exe bridge lipsă

Jurnal de urmă arată BRIDGE:MISSING target=<t> expected=<path>. Exe-urile C++ tray trăiesc în bin/CBE-Bridge-<Pretty>.exe. Dacă al dumneavoastră nu există, reconstruiți din sursă bridges_cpp/ (MSVC) sau trageți un .vsix proaspăt.
