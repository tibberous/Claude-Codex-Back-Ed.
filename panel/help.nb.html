Claude Codex — Black Edition

Frittstående AI-panel for VSCode. Chat med hvilken som helst LLM-leverandør (direkte API eller nettleserbru), med innebygd TTS, STT, vedlegg-til-fil, kommandopallett, multi-konto, skinning og en piksel-kjæledyr Tamagotchi.

Rask start ↑ topp

  1. Klikk Setup (trollstav-ikon) og gå gjennom veivisaren for å leggje til API-nøklane dine. Dei blir lagra i config.ini (som er gitignored – aldri committed).
  2. Klikk leverandør-pillen nede til venstre (for tida merkt «Claude Codex — Black Edition») for å byta hvilken AI du pratar med.
  3. Skriv i tekstfeltet og trykk Enter for å sende. Shift+Enter set inn ein ny linje.
  4. Trykk ↑ i eit tomt tekstfelt for å henta fram tidlegare spørsmål (PowerShell-stil historikk).

Kvar bru er eit lite C++-bakprogramm i bin/CBE-Bridge-<Target>.exe som opnar ein innlogga Chrome-profil, fangar prompten din og returnerer svaret frå modellen. Å velja ein bru-leverandør i Innstillingar startar automatisk det samsvarande bakprogrammet. Fyrste gang du brukar ein bru må du logga inn på nettstaden i Chrome-vindauget dess ein gong.

Bru-chat snakkar ein linje-protokoll på TCP: ein JSON-linje inn ({action:"chat", target, message, model}), ein JSON-linje ut. Ingen API-nøkkel kravd.

Sende meldingar ↑ topp

Tekstfelt
Skriv spørsmålet ditt. Enter sendar, Shift+Enter set inn ny linje. Medan eit svar streamer, blir ytterlegare spørsmål køa og sendt i rekkefølgje – plasshaldaren viser «Queue another message…» i denne tilstanden.
Send-knapp (kule)
Den runde knappen på høgre kant av tekstfeltet. Same som Enter. Viser visuelt tre tilstandar (idle / hover / aktiv).
Stopp-knapp
Nede til høgre i komponisten. Avbryt det strøymande svaret og alle køa meldingar. Strøyma tekst blir bevart; berre in-flight-førespørnaden blir avbroten.
Leverandør-pille
Nede til venstre i komponisten. Klikk for ein nedtrekk-liste med kvar leverandør du har konfigurert. Å velja ein ny startar automatisk dess bru (viss gjeldande) og postar ein bekreftings-toast.
Spørsmål-historikk
↑ / ↓ i eit tomt tekstfelt går bakover / framover gjennom dei siste 500 spørsmåla du sendte (PowerShell-stil). Historikk er lagra i prompt_history.txt i utvidingsmappa og overlever panel-omlasting.

Modaler & dialoger ↑ topp

Innstillingar-modal — leverandør / modell / utsjånad / språk / SFX
  • Leverandør: full nedtrekk av kvar direkte-API + bru-leverandør. Å velja ein byttar den aktive sesjonenen OG startar automatisk det samsvarande bru-bakprogrammet (viss gjeldande).
  • Modell: per-leverandør-liste over tillate modeller (t.d. claude-opus-4-7, claude-sonnet-4-6, claude-haiku-4-5 for Anthropic).
  • Utsjånad: visuelt tema. Sjå Utsjånader.
  • Språk: 39 språk tilgjengelege. Å byta gjenopptakningar strings-kartet og re-oversetter kvar tooltip / label / help-knapp live.
  • SFX-aktivert: slå UI-lydeffektar av/på (klikk, tikk, modal open/close, o.s.v.).
  • SFX-volum: 0–100 glider. Førehandsvisning live medan du dreggar.
  • Avbryt gjer endringar om på alle live-forhandsvisningar (SFX/utsjånad) du prøva; Lagra vedvik og utsender setProvider.

Kontoar & API-nøklar ↑ topp

Kvar leverandør kan ha fleire merkte kontoar – nyttig viss du vil byta mellom personleg og arbeid-nøklar, eller testa ein annan tier. Kontoar-modalen let deg:

Utsjånader ↑ topp

Visuelle tema for heile panelet – knappor, modaler, kodeblokker, til og med skrift. Vel ein i Innstillingar → Utsjånad. Kvar utsjånad lever i skins/<id>/ med ein manifest.xml (deklarerer fargane + aksent) og ein styles.css (overskriv CSS-variablar).

  • codex-black (standard) – mørk, monospace, neon-cyan aksent
  • glassy – frost-glass-overflatar over ein soft-bakgrunn
  • tamagotchi – lime-grøn LCD-handheld; auto-viser pet-widgeten dokka i komponisten-hjørne
  • office – Word-stil krem/blå-chrome
  • macos-color-dock / mint-dock – botn-dock-verktøylinjer med glassy-ikon
  • terminal / arch / kde / gnome / xfce / ubuntu / redhat – Linux-skrivebord-tema

Modal-fargane kjem frå <colors>-inngångar i kvar utsjånad sitt manifest og blir pusja på :root som --cbe-modal-* variablar so kvar modal (inkludert denne hjelpa) rendar in-theme.

Utvidingar ↑ topp

Mini-app-ar som lever inne i CBE. Kvar er ein mappe under extensions/<id>/ med:

  • manifest.xml — id, namn, versjon, forfattar, skildring, entry HTML, ikon (emoji eller icon.svg)
  • extension.html (eller kva som helst manifest sin <entry> seier) — den faktiske app-en

Klikk Utvidingar for å bla kva som er installert, fest til verktøylinja, installera nye frå offentleg katalog, eller fjerna frå disk. Festade ID-ar lever i extensions/_pinned.json.

Auto-oppdatering (push / pull) ↑ topp

CBE synkroniserar sin kjelde mellom maskinane via ein WinSCP-push + HTTPS-pull-kanal.

Push (berre admin)

Viss [updates] is_admin = true i config.ini, kvar aktivering køyrer ein bakgrunns WinSCP synchronize remote -mirror som pushar utvidingsmappa til /home/trentontompkins.com/cbe på tenaren. Manuell trigger: /push skråstrek-kommando. Ekskluderer per-maskin-tilstand: data/ (1.74 GB Chrome-profil), bridges/, node_modules/, .git/, logs/, chats/, config.ini, prompt_history.txt, domains.txt, wake.txt.

Pull (kvar klient)

4 sekund etter aktivering, kvar klient hentar https://trentontompkins.com/cbe/manifest.xml.php og MD5-samanliknar per-fil mot lokale kopiar. Berre endra/manglande filer blir deira ned over plain HTTPS GET. Ekskluderte stiar blir ALDRI henta: config.ini, data/, bridges/, extension.js, panel/panel.js, panel/index.html, package.json, bygge-verktøy – årsaka er at kjelde skip via .vsix og tenaren sin eldre kopi må ikkje knøkkra in-progress dev-arbeid.

Varmglading ↑ topp

To opplastings-stiar er eksponerte via høgreklikk-menyen:

  • Opplast panelet på nytt – les på nytt panel/index.html + kvar JS/CSS-ressurs med ein per-fil ?v=<mtime> cache-buster og tildelar på nytt panel.webview.html. Plukk opp panel.js / skin CSS / dotmatrix-endringar utan å starta VSCode på nytt. Utvidingsverten held seg klar (ditt terminal, supervisor, meldings-handsamarar, chat-historikk alle vedhuld).
  • Opplast vindauget på nytt – firer workbench.action.reloadWindow. Bruk berre når du har redigert extension.js (vert-sidekode) og Opplast panelet på nytt ikkje er nok.

Skin CSS-endringar auto-gjeld òg via panelet sin eksisterande skin-overvåkar – ingen meny-klikk nødvendig.

Feilsøking ↑ topp

«bridge X chat failed: api key empty in config.ini»

smart_bridge.py-daemonen var bufring ein gitt gate-kontroll i minne. Fiksa i C++-exe-routing-pivot. Viss du enno ser ho, drepa forelda daemonar:

powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*smart_bridge.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
«copilot has no public REST API — use the browser bridge»

Gitt extension.js var rutering bru-chat gjennom REST-routeren i stad for den faktiske C++-tray-exe. Opplast Vindauget på nytt for å plukk opp den fiksa extension.js, då chat går rett til bin/CBE-Bridge-Copilot.exe.

HTTP 404 model: sonnet-4.6

Forelda kort-alias i Claude-bru-konfigurasjon. Fiksa – fulle ID-ar (claude-sonnet-4-6, claude-opus-4-7, claude-haiku-4-5) blir no brukt.

Eg redigerte ein fil men panelet viser ikkje endringa
  1. Viss det er panel.js / skins/*.css / index.html → høgreklikk → Opplast panelet på nytt.
  2. Viss det er extension.js / bridges_cpp/*.py → høgreklikk → Opplast vindauget på nytt.
  3. Viss du ikkje kan nå menyen (t.d. menyen sjølv er ikkje lasta enno), start ein ny VSCode-instans med ein isolert user-data-dir:
    code --user-data-dir="$env:USERPROFILE\.cbe-edh" --extensionDevelopmentPath="C:\Users\moren\Desktop\Claude Codex Black"
STT mislukkas med «not-allowed»

VSCode sandkassar webview-en frå mikrofon-løyve. CBE auto-faller-tilbake til Windows SAPI (System.Speech.Recognition) starta via PowerShell. Du kan trengja å gje mikrofon-tilgang på OS-nivå (Settings → Privacy → Microphone).

Bru-exe manglar

Spor-log viser BRIDGE:MISSING target=<t> expected=<path>. C++-tray-exe-ane lever i bin/CBE-Bridge-<Pretty>.exe. Viss dine ikkje eksisterer, bygg på nytt frå bridges_cpp/ kjelde (MSVC) eller hent ein frisk .vsix.
