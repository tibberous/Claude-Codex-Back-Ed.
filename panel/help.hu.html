Gyors kezdés ↑ teteje

  1. Kattintson a Telepítésre (varázspálca ikon), és végigmenjen a varázslón az API kulcsok megadásához. Ezek a config.ini fájlba kerülnek (amely .gitignored — sohasem commitálódik).
  2. Kattintson a bal alsó szolgáltató pilulára (jelenleg „Codex Black Ed." címkézett) a használt AI váltásához.
  3. Írjon a szövegmezőbe és nyomja meg az Enter billentyűt az üzenet küldéséhez. Shift+Enter új sort szúr be.
  4. Nyomja meg az ↑ billentyűt egy üres szövegmezőben az előző promptok visszahívásához (PowerShell-stílusú előzmények).

Minden híd egy kis C++ tray exe a bin/CBE-Bridge-<Target>.exe helyen, amely megnyit egy bejelentkezett Chrome profilt, elfogja a promptot, és visszaadja a modell válaszát. A híd szolgáltató kiválasztása a Beállítások között automatikusan elindítja a megfelelő exe fájlt. Az első alkalommal, amikor hídat használ, be kell jelentkeznie az oldalra annak Chrome ablakában.

A híd csatornázása egy sor-protokollt beszél TCP-n: egy JSON sor be ({action:"chat", target, message, model}), egy JSON sor ki. Nincs szükség API kulcsra.

Üzenetek küldése ↑ teteje

Szövegmező
Írja be a promptot. Enter küld, Shift+Enter új sort szúr be. Amíg egy válasz streamelődik, a további promptok sorba kerülnek és sorrendben küldődnek — a helyőrző ebben az állapotban „Sorba helyez egy másik üzenetet…" szöveget mutat.
Küldés gomb (orb)
A szövegmező jobb szélén lévő kerek gomb. Ugyanaz, mint az Enter. Vizuálisan három állapotot jelenít meg (üresjárat / hover / aktív).
Leállítás gomb
A komponáló jobb alsó sarka. Visszavon az aktuálisan streamelő válaszat és minden sorba helyezett üzenetet. A streamelt szöveg megmarad; csak a szállítás alatt álló kérés törlődik.
Szolgáltató pilula
A komponáló bal alsó sarka. Kattintson egy legördülő listához az összes konfigurált szolgáltatóhoz. Az új kiválasztása automatikusan elindítja a hidat (ha alkalmazható) és egy megerősítő toastot küld.
Prompt előzmények
↑ / ↓ egy üres szövegmezőben visszafelé / előrefelé halad az utolsó 500 elküldött prompton keresztül (PowerShell-stílusú). Az előzmények a prompt_history.txt helyen vannak tárolva a bővítmény mappájában, és túlélik a panel újratöltéseit.

Az adott régió nyers HTML/markdown-ját mutatja — vagy egy kódblokk vagy a teljes panel DOM. Hasznos a bőr/CSS hibák hibakereséshez.

Névjegy új
Egy kis panelbeli párbeszédablak a verzióval, szerzővel, licenccel, repo hivatkozással, portfólióval és elérhetőségi telefonszámmal. Bezáródik a háttérkattintásra, × gombra vagy az Esc billentyűre.

Kiváltja a workbench.action.reloadWindow parancsot. Csak akkor használja, ha szerkesztette az extension.js fájlt (gazdagép oldali kód), és a panel frissítés nem elég. Ez egy teljes VSCode ablak újratöltés.

Modális ablakok és párbeszédek ↑ teteje

Beállítások modális ablak — szolgáltató / modell / bőr / nyelv / SFX
  • Szolgáltató: teljes legördülő az összes közvetlen API + híd szolgáltatóhoz. Egy kiválasztása a függetlenül módosít az aktív munkamenetet ÉS automatikusan elindítja a megfelelő híd exe-t (ha alkalmazható).
  • Modell: szolgáltatónkénti engedélyezett modellek listája (pl. claude-opus-4-7, claude-sonnet-4-6, claude-haiku-4-5 az Anthropic számára).
  • Bőr: vizuális téma. Lásd: Bőrmódok.
  • Nyelv: 39 lokalizáció elérhető. A váltás élőben újra lekéri a karakterláncok térképét és újra lefordítja az összes eszköztippet / címkét / súgógombot.
  • SFX engedélyezve: UI hangeffektusokat váltva (kattintások, tikkelés, modális megnyitás/zárás, stb.).
  • SFX hangerő: 0–100 csúszka. Az élő vetítés húzása közben előnézet.
  • Mégse visszavon minden élő előnézetet (SFX/bőr), amit kipróbált; a Mentés megőrzi és egy setProvider bocsát ki.
Telepítési varázsló — többlépcsős API kulcs bevitelezési

Végigvezetés minden integrációhoz. Minden lépés elküld hitelesítési adatokat, és írja őket a config.ini fájlba. A Kihagyás előrelépkedik írás nélkül; a Tovább ír és előrehalad; az utolsó lépés Kész gombja zár. A lépések között: Anthropic, OpenAI, Gemini, xAI/Grok, GitHub PAT, Email/SMTP (Gmail alkalmazás jelszó), Cloudflare, Twilio, ElevenLabs, Stability AI, Runway, SendGrid, NameSilo és még sok más.

Fiókok modális ablak — többfiókos API kulcs kezelő

Minden szolgáltatóhoz több címkézett fiók kezelése (pl. „személyes", „munka"). Váltson azt, amelyik aktív munkamenetenként a többi felülírása nélkül. A kulcsok maszkolt végről végre vannak tárolva és szolgáltatónként mentve a config.ini fájlban.

Domének modális ablak — NameSilo

Felsorolja a NameSilo fiók összes domainját névszerverekkel + regisztrációs dátumokkal. A Frissítés gomb egy friss API letöltést kényszerít (egyébként a domains.txt fájlban gyorsítótáraz).

Kézikönyv modális ablak

Egy projekt kézikönyv HTML-ét jeleníti meg (rendszer-prompt referenciaként szándékolt, amelyet a modell konzultálhat). Projektenkénti konfigurálható.

Tárolt promptok modális ablak

Beszúrható prompt sablonok a stored_prompts/ mappából. Minden fájl egy sablon; a fájlnév előtagja NN- a rendezési sorrendet szabályozza. A „+" gomb egy újat hoz létre.

Csevegés előzmény modális ablak

Válasszon egy UTC dátumot a csevegési napló betöltéséhez a chats/<date>.log fájlból. Csak olvasható.

Bővítmények modális ablak

Kártyák az összes telepített bővítményhez. Rögzítés az eszköztárhoz / rögzítés feloldása, telepítés a nyilvános katalógusból (extensions.xml.php a szerveren), vagy eltávolítás a lemezről.

Módosítási napló modális ablak

A panel/change_log.html fájlt jeleníti meg — a csomagolt kiadási megjegyzések. A tools/build_changelog.py használatával generálva.

Forrás megtekintése modális ablak

Szép-nyomtat bármilyen kódblokk vagy a panel teljes HTML-jét Prism szintaxis kiemelésével és egy Másolás gombbal. Jobb kattintásra → Forrás megtekintése útvonalon érhető el.

Auto Prompt modális ablak

Parancs karakterláncot és visszaszámlálási időközt konfigurálhat. Az asszisztens minden válasza után a visszaszámlálás csökken; amikor nullára ér, a CBE automatikusan elküldi a konfigurált parancsot. Az Auto Prompt eszköztár gomb segítségével be-/kikapcsol.

Beállítások ↑ teteje

Az összes beállítás az alábbi helyek egyikén él:

  • workspaceState (VSCode-kezelés, munkaterületenként) — szolgáltató, modell, bőr, nyelv, sfx engedélyezve/hangerő, betűméret.
  • config.ini (bővítmény gyökércsomópontja, gitignored) — API kulcsok + integrációnkénti hitelesítési adatok.

A beállítások automatikusan megmaradnak a panel frissítésein keresztül. A Beállítások modális ablak a biztonságos módja a bármi megváltoztatásának; a config.ini közvetlen szerkesztése is működik.

Fiókok és API kulcsok ↑ teteje

Minden szolgáltatónak több címkézett fiókja lehet — hasznos, ha személyes és munka kulcsok között szeretne váltani, vagy egy másik szintet tesztel. A Fiókok modális ablak lehetővé teszi:

  • Egy új fiók hozzáadása címkével + kulccsal
  • Egy meglévő fiók szerkesztése (átcímkézés, kulcs cseréje)
  • Az aktuális munkamenetre aktív fiók beállítása
  • Egy fiók eltávolítása

A kulcsok maszkolt (csak az utolsó négy látható) módon vannak tárolva a config.ini fájlban. A workspaceState-ben nincs nyílt szöveges másolat.

Tamagotchi háziállat ↑ teteje

A Tamagotchi egy pixelart háziállat, amely a panelben él a tamagotchi bőrön alatt. Öregszik, éhes/piszkos lesz, játszható vele, és ha elhanyagolja, meghal. Az állapot megmarad a workspaceState fájlban.

Bőrmódok ↑ teteje

A teljes panel vizuális témái — gombok, modális ablakok, kódblokkok, még betűtípus is. Válasszon egyet a Beállítások → Bőr alatt. Minden bőr a skins/<id>/ mappában él egy manifest.xml (nyilatkozatok szín + hangsúly) és egy styles.css (CSS változók felülírása).

  • codex-black (alapértelmezett) — sötét, monospace, neon-cyan hangsúly
  • glassy — fagyott-üveg felületek egy puha háttér fölött
  • tamagotchi — lime-zöld LCD kézi konzol; automatikusan megjeleníti a pet widgetet a komponáló sarkára csatornázva
  • office — Word-stílusú krém/kék chrome
  • macos-color-dock / mint-dock — alsó-dock eszköztárak fagyott ikonokkal
  • terminal / arch / kde / gnome / xfce / ubuntu / redhat — Linux asztali témák

A modális ablakok színei az egyes bőrmódok manifest <colors> bejegyzéseiből származnak, és a :root osztályba kerülnek --cbe-modal-* változókként, így minden modális ablak (ezt a súgót is beleértve) témában jelenik meg.

Bővítmények ↑ teteje

Mini-alkalmazások, amelyek a CBE-n belül élnek. Mindegyik a extensions/<id>/ mappa alatt található:

  • manifest.xml — id, név, verzió, szerző, leírás, bejegyzés HTML, ikon (emoji vagy icon.svg)
  • extension.html (vagy amit a manifest <entry> mondat) — az aktuális alkalmazás

Kattintson a Bővítmények gombra a telepítettekhez, rögzítés az eszköztárhoz, telepítés a nyilvános katalógusból, vagy eltávolítás a lemezről. A rögzített ID-k a extensions/_pinned.json mappában élnek.

Automatikus frissítés (push / pull) ↑ teteje

A CBE szinkronizálja a forráskódját gépek között egy WinSCP push + HTTPS pull csatornán.

Push (csak admin)

Ha a [updates] is_admin = true a config.ini fájlban, az aktiváláskor egy háttér WinSCP synchronize remote -mirror fut, amely a bővítmény mappáját a szerveren a /home/trentontompkins.com/cbe helyre nyomja. Kézi aktiválás: /push slash parancs. Kizár gépenkénti állapotot: data/ (1,74 GB Chrome profilok), bridges/, node_modules/, .git/, logs/, chats/, config.ini, prompt_history.txt, domains.txt, wake.txt.

Pull (minden ügyfél)

Az aktiválást követő 4 másodperc után minden ügyfél letölti a https://trentontompkins.com/cbe/manifest.xml.php fájlt, és MD5-összehasonlít fájlonként az ismert helyi másolatokkal. Csak módosított/hiányzó fájlok töltődnek le egyszerű HTTPS GET-en keresztül. A kizárt útvonalak NEM lesznek soha lehúzva: config.ini, data/, bridges/, extension.js, panel/panel.js, panel/index.html, package.json, szerkesztési eszközök — az indoka az, hogy a forrás a .vsix-en keresztül szállítódik, és a szerver régebbi másolata nem szabad, hogy tönkre tegyen a folyamatban lévő fejlesztési munkákat.

Hot reload ↑ teteje

Két frissítési út van a jobb kattintás menün keresztül:

  • Panel újratöltése — újra beolvassa a panel/index.html + minden JS/CSS eszközt egy fájlonkénti ?v=<mtime> cache-buster-rel, és újra hozzárendeli a panel.webview.html fájlt. Felveszi a panel.js / bőr CSS / dotmatrix szerkesztéseket a VSCode újraindítása nélkül. A bővítményi gazdafolyamat él (a terminál, felügyelő, üzenetkezelő, csevegés előzmények megmaradnak).
  • Ablak újratöltése — kiváltja a workbench.action.reloadWindow parancsot. Csak akkor használja, ha az extension.js (gazdagép oldali kód) szerkesztett, és a panel frissítés nem elegendő.

A bőr CSS szerkesztéseit az panel meglévő bőr figyelőjén keresztül auto-alkalmazza — nem szükséges menü kattintás.

Hibaelhárítás ↑ teteje

„híd X csevegés meghiúsult: API kulcs üres a config.ini fájlban"

A smart_bridge.py démon memóriában egy régi kapu-ellenőrzést gyorsítótárázott. A C++-exe útválasztási forgásban rögzítve. Ha még mindig látod, öldd meg az elavult démonokat:

powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*smart_bridge.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
„a Copilot nincs nyilvános REST API — használja a böngésző hidat"

Az extension.js régi verzió a híd csevegést a REST útválasztón keresztül vezette a tényleges C++ tray exe helyett. Ablak újratöltése a rögzített extension.js felvételéhez, majd a csevegés közvetlenül a bin/CBE-Bridge-Copilot.exe fájlba fog menni.

HTTP 404 modell: sonnet-4.6

Elavult rövid alias a Claude híd konfigban. Rögzítve — teljes ID-k (claude-sonnet-4-6, claude-opus-4-7, claude-haiku-4-5) vannak használatban.

Szerkesztettem egy fájlt, de a panel nem mutatja a változást
  1. Ha ez a panel.js / skins/*.css / index.html → jobb kattintás → Panel újratöltése.
  2. Ha ez az extension.js / bridges_cpp/*.py → jobb kattintás → Ablak újratöltése.
  3. Ha nem tudod elérni a menüt (pl. a menü még nem töltődött be), indítson egy új VSCode példányt elszigetelt felhasználó-adatok könyvtárral:
    code --user-data-dir="$env:USERPROFILE\.cbe-edh" --extensionDevelopmentPath="C:\Users\moren\Desktop\Codex Black"
STT meghiúsul a „not-allowed" üzenettel

VSCode elszigeteli a webview-t a mikrofon engedélyből. A CBE automatikusan visszaesik a Windows SAPI-ra (System.Speech.Recognition), amelyet PowerShell-en keresztül indít. Az OS szintjén mikrofonhozzáférést kell engedélyeznie (Beállítások → Adatvédelem → Mikrofon).

Híd exe hiányzik

A nyomkövetési napló ezt mutatja: BRIDGE:MISSING target=<t> expected=<path>. A C++ tray exe-ik a bin/CBE-Bridge-<Pretty>.exe mappában élnek. Ha az övé nem létezik, építse meg a bridges_cpp/ forráskódból (MSVC) vagy húzza le egy friss .vsix-et.
