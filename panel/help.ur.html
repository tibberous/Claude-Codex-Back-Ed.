تیز رفتار شروعات ↑ اوپر

  1. سیٹ اپ (جادو کی چھڑی کا آئیکن) پر کلک کریں اور اپنی API کیز درج کرنے کے لیے جادوگر کے ذریعے جائیں۔ وہ config.ini میں محفوظ ہو جاتے ہیں (جو gitignored ہے — کبھی کمٹ نہیں ہوتا)۔
  2. نیچے بائیں طرف فراہم کنندہ پل پر کلک کریں (فی الوقت "Codex Black Ed." لیبل شدہ) یہ سوئچ کرنے کے لیے کہ آپ کس AI سے بات کر رہے ہیں۔
  3. ٹیکسٹ ایریا میں ٹائپ کریں اور بھیجنے کے لیے Enter دبائیں۔ Shift+Enter ایک نئی لائن شامل کرتا ہے۔
  4. خالی ٹیکسٹ ایریا میں ↑ دبائیں پچھلے prompts یاد کرنے کے لیے (PowerShell سبک تاریخ)۔

ہر برج bin/CBE-Bridge-<Target>.exe میں ایک چھوٹا C++ ٹریے exe ہے جو ایک لاگ ان شدہ Chrome پروفائل کھولتا ہے، آپ کے prompt کو روکتا ہے، اور ماڈل کا جواب واپس کرتا ہے۔ سیٹنگز میں برج فراہم کنندہ کو منتخب کرنے سے ملتی جلتی exe خود بخود شروع ہو جاتی ہے۔ پہلی بار جب آپ کسی برج کا استعمال کرتے ہیں تو آپ کو اس کی Chrome ونڈو میں سائٹ میں لاگ ان کرنا ہوگا۔

پیغامات بھیجنا ↑ اوپر

ٹیکسٹ ایریا
اپنا prompt ٹائپ کریں۔ Enter بھیجتا ہے، Shift+Enter ایک نئی لائن شامل کرتا ہے۔ جب کوئی جواب سٹریمنگ ہو رہا ہے تو اضافی prompts queued ہوتے ہیں اور ترتیب سے بھیجے جاتے ہیں — placeholder اس حالت میں "ایک اور پیغام درج کریں..." دکھاتا ہے۔
بھیجیں بٹن (orb)
ٹیکسٹ ایریا کے دائیں کنارے پر گول بٹن۔ Enter کے برابر۔ بصری طور پر تین حالتیں دکھاتا ہے (idle / hover / active)۔
رکیں بٹن
کمپوزر کے نیچے دائیں۔ فی الوقت سٹریمنگ جواب اور کسی بھی queued پیغامات کو منسوخ کرتا ہے۔ سٹریم شدہ متن برقرار رہتا ہے؛ صرف in-flight درخواست منسوخ ہو جاتی ہے۔
فراہم کنندہ پل
کمپوزر کے نیچے بائیں۔ ہر فراہم کنندہ کی ڈراپ ڈاؤن کے لیے کلک کریں جو آپ نے سیٹ اپ کیا ہے۔ ایک نیا منتخب کرنا خود بخود اس کے برج کو شروع کرتا ہے (اگر قابلِ اطلاق) اور ایک تصدیقی ٹوسٹ پوسٹ کرتا ہے۔
Prompt تاریخ
خالی ٹیکسٹ ایریا میں ↑ / ↓ پچھلے 500 prompts کے ذریعے آگے پیچھے چلتا ہے جو آپ نے بھیجے ہیں (PowerShell سبک)۔ تاریخ ایکسٹینشن فولڈر میں prompt_history.txt میں محفوظ ہے اور پینل ری لوڈز میں بچی رہتی ہے۔

ماڈلز اور ڈائیلاگز ↑ اوپر

ترتیبات modal — فراہم کنندہ / ماڈل / skin / زبان / SFX
  • فراہم کنندہ: ہر direct-API + برج فراہم کنندہ کی مکمل dropdown۔ ایک کو منتخب کرنا فعال سیشن کو سوئچ کرتا ہے اور matching برج exe خود بخود شروع کرتا ہے (اگر قابل اطلاق)۔
  • ماڈل: فی فراہم کنندہ ماڈل کی اجازت شدہ فہرست (مثلاً claude-opus-4-7، claude-sonnet-4-6، claude-haiku-4-5 Anthropic کے لیے)۔
  • Skin: بصری تھیم۔ Skins دیکھیں۔
  • زبان: 39 locales دستیاب۔ سوئچنگ strings map کو دوبارہ pull کرتا ہے اور ہر tooltip / label / help بٹن کو زندہ ترجمہ کرتا ہے۔
  • SFX فعال: UI سائونڈ افیکٹس کو ٹوگل کریں (clicks، ticks، modal open/close، وغیرہ)۔

ایکسٹینشنز ↑ اوپر

CBE کے اندر Mini-apps۔ ہر extensions/<id>/ کے تحت ایک فولڈر ہے جس میں:

  • manifest.xml — id، نام، ورژن، مصنف، description، entry HTML، icon (emoji یا icon.svg)
  • extension.html (یا جو بھی manifest کی <entry> کہے) — اصل app

ایکسٹینشنز پر کلک کریں تاکہ اسے براؤز کریں جو انسٹال ہے، ٹول بار میں pin کریں، عوامی کیٹلاگ سے نئے انسٹال کریں، یا ڈسک سے ہٹائیں۔ Pinned IDs extensions/_pinned.json میں رہتے ہیں۔

خودکار اپڈیٹ (push / pull) ↑ اوپر

CBE WinSCP push + HTTPS pull channel کے ذریعے machines کے درمیان اپنے source کو sync کرتا ہے۔

Push (صرف admin)

اگر config.ini میں [updates] is_admin = true ہے تو ہر activation background WinSCP synchronize remote -mirror چلاتا ہے جو ایکسٹینشن فولڈر کو سرور پر /home/trentontompkins.com/cbe میں push کرتا ہے۔ Manual trigger: /push slash command۔ فی machine state excludes کرتا ہے: data/ (1.74 GB Chrome profiles)، bridges/، node_modules/، .git/، logs/، chats/، config.ini، prompt_history.txt، domains.txt، wake.txt۔

Pull (ہر client)

activation کے بعد 4 سیکنڈ میں ہر client https://trentontompkins.com/cbe/manifest.xml.php fetch کرتا ہے اور MD5 compare کرتا ہے فی فائل مقامی کاپیز کے خلاف۔ صرف تبدیل شدہ/missing فائلیں plain HTTPS GET پر download ہوتی ہیں۔ Excluded paths کبھی نہیں pull ہوتے: config.ini، data/، bridges/، extension.js، panel/panel.js، panel/index.html، package.json، بلڈ ٹولز — rationale ہے کہ source .vsix کے ذریعے ships ہوتا ہے اور سرور کی پرانی کاپی in-progress dev کو clobber نہیں کرنی چاہیے۔

ہاٹ ری لوڈ ↑ اوپر

دو reload راستے دائیں کلک مینو کے ذریعے expose ہیں:

  • پینل دوبارہ لوڈ کریں — panel/index.html + ہر JS/CSS asset کو دوبارہ پڑھتا ہے ایک فی فائل ?v=<mtime> cache buster کے ساتھ اور panel.webview.html کو دوبارہ assign کرتا ہے۔ VSCode کو reboot کیے بغیر panel.js / skin CSS / dotmatrix ترمیمات اٹھاتا ہے۔ ایکسٹینشن host زندہ رہتا ہے (آپ کا terminal، supervisor، message handlers، چیٹ تاریخ سب برقرار رہتے ہیں)۔
  • ونڈو دوبارہ لوڈ کریں — workbench.action.reloadWindow کو محرک کرتا ہے۔ صرف اس وقت استعمال کریں جب آپ نے extension.js (host side code) ترمیم کیا ہے اور پینل reload کافی نہیں ہے۔

Skin CSS ترمیمات بھی پینل کے موجودہ skin watcher کے ذریعے خود بخود apply ہوتی ہیں — کوئی مینو کلک نہیں چاہیے۔
