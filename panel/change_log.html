6. fix(supervisor): NSSM install quoting + :3434 liveness probe

22d4579 Trent Tompkins 22h ago
  • The first install attempt failed because `nssm install <name> <app> <args>`
  • fed PowerShell a giant arg-line; PS stripped the outer quotes around
  • `"C:\Users\moren\AppData\Local\Programs\Microsoft VS Code\Code.exe"`, the
  • spaces in `Microsoft VS Code` tokenized into separate commands, and the
  • install transcript shows `ERROR: The term 'Code.exe' is not recognized`.
  • Service registered with EMPTY AppParameters in registry, so `sc start`
  • silently did nothing.
  • Fix:
  • - Stub-then-set install pattern: `nssm install <name> <psExe>` then
  • `nssm set <name> Application/AppParameters/AppDirectory/...` one
  • property at a time. Each value is wrapped in PowerShell single-quotes
  • (literal strings — no $-expansion, no escape parsing) so spaces can't
  • re-tokenize. AppParameters embeds its own double-quotes around the
  • -File and -CodePath paths so NSSM's stored value remains a valid
  • command-line for CreateProcess.
  • - SDDL widening switched to single-quoted form too.
  • Supervisor :3434 HTTP listener:
  • - `vscode_supervisor.ps1` now binds `http://127.0.0.1:3434/` via
  • `System.Net.HttpListener` and replies 200 OK with a JSON status blob
  • (pid, relaunch count, last relaunch ts, target Code path). Drained
  • every tick of the main loop and after every relaunch so polls stay
  • responsive while VSCode boots back up.
  • - Listener closes cleanly on stop signal alongside the existing
  • `Console.CancelKeyPress` handler.
  • Panel button glow now tracks HTTP liveness:
  • - New `_supervisorHttpAlive()` in extension.js does a 700ms GET to
  • :3434 and resolves true on 200. The `monitorStatus` handler reports
  • `{running: alive, state: sc-state, httpAlive: alive}`. Glow is on
  • iff the script is actually responding — protects against "SCM thinks
  • the service is running but the script crashed silently" false
  • positives the old `sc query`-only check produced.
