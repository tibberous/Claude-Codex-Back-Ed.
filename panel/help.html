Quick start ↑ top

  1. Click Setup (wand icon) and walk through the wizard to enter your API keys. They get saved to config.ini (which is gitignored — never committed).
  2. Click the provider pill at the bottom-left (currently labeled "Codex Black Ed.") to switch which AI you're talking to.
  3. Type into the textarea and press Enter to send. Shift+Enter inserts a newline.
  4. Press ↑ in an empty textarea to recall previous prompts (PowerShell-style history).

Each enabled bridge is a small C++ tray exe at bin/CBE-Bridge-<Target>.exe that opens a logged-in Chrome profile, intercepts your prompt, and returns the model's reply. Picking a bridge provider in Settings auto-launches the matching exe. First time you use a bridge you must log into the site in its Chrome window once.

Bridge chat speaks a line-protocol on TCP: one JSON line in ({action:"chat", target, message, model}), one JSON line out. No API key required.

Anatomy of a .bridge file

<?xml version="1.0" encoding="UTF-8"?>
<bridge id="deepseek">
  <name>DeepSeek</name>
  <author>Claude Opus 4.7</author>
  <released>2026-05-24</released>
  <version>1.0.0</version>
  <description>DeepSeek V3 + R1 via chat.deepseek.com.</description>
  <mainUrl>https://chat.deepseek.com/</mainUrl>
  <loginUrl>https://chat.deepseek.com/sign_in</loginUrl>
  <createAccountUrl>https://chat.deepseek.com/sign_up</createAccountUrl>
  <bridgePort>8794</bridgePort>
  <cdpPort>9794</cdpPort>
  <exeName>CBE-Bridge-DeepSeek.exe</exeName>
  <iconFile>icons/deepseek.png</iconFile>
  <enabled>true</enabled>
  <defaultModel>deepseek-chat</defaultModel>
  <model>deepseek-chat</model>
  <model>deepseek-reasoner</model>
</bridge>

Drop a new .bridge file in extensions/ and reload — it shows up in Providers, the Accounts modal, and the Extensions marketplace card grid.

Bridge Operator ↑ top

The Bridge Operator is the vision-pilot LLM that drives the browser bridges. When you chat through a bridge (ChatGPT / Grok / Gemini / Claude / Copilot / DeepSeek), the operator reads screenshots of the offscreen Chromium, figures out where to click and type, and emits the actions that deliver your prompt and read back the reply. It's separate from the provider you're chatting with: the operator is the brain that operates the browser.

Pick the operator provider

Open Settings → Bridge Operator and choose which LLM drives the bridges:

ProviderAuthNotes
Azure OpenAI default[azure] api_key + endpointDefault operator. The model picker lists your Azure deployments.
OpenAI[api_keys] openai_api_keyStandard OpenAI vision-capable models.
Anthropic[api_keys] anthropic_api_keyClaude vision models.
Google (Gemini API key)[api_keys] gemini_api_keyGemini via API key.
Google Vertex (Cloud / ADC)Application Default CredentialsNo key in config.ini — uses your local gcloud ADC login.

Load models / deployments

Below the provider dropdown is a model selector with a Load button. Click Load to fetch the selected provider's live list (Azure surfaces deployments; the others surface models) into the dropdown — a status line shows progress / errors. Your choice is remembered per provider, so switching operator providers back and forth keeps each one's selected model.

The operator only matters for the browser bridges. Direct-API providers talk to their endpoint directly and don't use the vision pilot.

Sending messages ↑ top

Textarea
Type your prompt. Enter sends, Shift+Enter inserts a newline. While a reply is streaming, additional prompts are queued and sent in order — the placeholder shows "Queue another message…" during this state.
Send button (orb)
The round button at the right edge of the textarea. Same as Enter. Visually shows three states (idle / hover / active).
Stop button
Bottom-right of the composer. Cancels the currently-streaming reply and any queued messages. Streamed text is kept; only the in-flight request is aborted.
Provider pill
Bottom-left of the composer. Click for a dropdown of every provider you have configured. Picking a new one auto-starts its bridge (if applicable) and posts a confirmation toast.
Prompt history
↑ / ↓ in an empty textarea walks backward / forward through the last 500 prompts you've sent (PowerShell-style). History is stored at prompt_history.txt in the extension folder and survives panel reloads.

Toolbar buttons ↑ top

Listed in toolbar order. All tooltips are localizable per-language via languages/*.xml.

New conversation addBtn
Clears the current thread, wipes the in-memory conversation state, and starts fresh. The previous thread is preserved on disk under chats/<UTC-date>.log so nothing is lost. Equivalent to /clear.
Stored prompts storedPromptsBtn
Opens a modal listing every saved prompt template under stored_prompts/. Click one to insert it into the textarea; the "+" button adds a new template. Templates support variable substitution.
Chat history chatHistoryBtn
Browses the on-disk chat log (one file per UTC date under chats/). Pick a date to scroll back through past conversations.
Attach file attachFileBtn
Opens a file picker. Selected file is uploaded with the next prompt — images go inline (vision), text/code files become a fenced block in your prompt. Supports multi-attach.
Read aloud (TTS) ttsBtn
Speaks the most recent assistant reply aloud. Uses ElevenLabs (if [elevenlabs] api_key is set) or falls back to Windows SAPI. Right-click toggles auto-read mode where every new reply is spoken automatically — the button gets an animated indicator while active.
Speech to text (STT) sttBtn
Records microphone audio and transcribes into the textarea. Tries the webview's Web Speech API first; if that fails (not-allowed, common in VSCode sandboxes), falls back to Windows SAPI (System.Speech.Recognition) launched on the host via PowerShell. Click again to stop.
Auto Prompt autoReplyBtn
Opens the Auto Prompt modal. Define a prompt + a countdown interval; after every assistant reply the countdown ticks and re-sends the auto-prompt automatically when it hits zero. Useful for "keep going", "next step", repeated tool sessions. Click again to disable.
Wake-up response wakeUpBtn
Edits the wake-up message stored at wake.txt. The wake-up is what Auto Prompt sends if it detects the model has stalled — generally a short ping like "Hey! Continue."
Show command menu showCommandsBtn
Opens the slash-command palette in a modal. See Slash commands for the full list. Same as typing / at the start of the textarea.
Compact conversation compactBtn
Posts a summarize-and-prune request that replaces the current thread with a condensed recap. Equivalent to /compact. Useful when the conversation has grown long and you want to keep context but stop burning tokens on re-sending the whole history.
Handbook handbookBtn
Opens the employee/project handbook modal. Loads handbook.html or whatever document is configured. Used as a system-prompt reference the model can be asked to consult.
Settings settingsBtn
Opens the Settings modal (provider, model, skin, language, SFX). See Settings.
Accounts accountsBtn
Opens the multi-account manager. Add / edit / remove API keys per provider, switch between them per session. See Accounts.
Extensions extensionsBtn
Opens the in-panel extensions browser. Lists what's installed under extensions/ (each with a manifest.xml + an entry HTML), lets you pin extensions to the toolbar, install new ones from the public catalog, or remove them.
Project folder project pill
The project-folder pill next to the provider pill is the project-folder control. Click it to pick a folder when none is set, or to reveal the current folder in the file explorer when one is. The small ✕ on the pill clears it back to "no project folder". The chosen directory is used by Attach File, Terminal, Git, and any tools that need a project root. (The dock's separate Project-Folder button was removed as redundant — the pill does everything it did.)
Browser browserBtn
Opens a side-by-side QtWebEngine browser pane for quick lookups without leaving the panel.
VSCode monitor monitorBtn
Toggles the VSCode supervisor watchdog — a background process that restarts VSCode if it crashes. Left-click toggles run/stop, right-click opens the supervisor's trace channel.
Terminal terminalBtn
Opens a VSCode integrated terminal in the project folder. If the project folder isn't set, falls back to your Desktop. Reuses one persistent terminal labeled "CBE".
Setup wizard setupBtn
Walks you through every API key + integration the extension knows about (~12 steps). See Setup wizard.
Git gitBtn

GitHub githubBtn

Right-click menu ↑ top

Right-click on chat text or a code block to get the CBE context menu. Right-click on the prompt textarea now opens the native browser menu (Copy / Cut / Paste / Delete / Select All) instead.

Copy / Copy code block
Copies the current selection. If no selection but you right-clicked on a <pre><code>, it copies the entire code block.
View Source
Shows the raw HTML/markdown of the clicked region — either a code block or the whole panel DOM. Useful for debugging skin/CSS issues.
Open DevTools
Asks VSCode to open its Developer Tools so you can inspect the webview live.
Settings new
Opens the same Settings modal the toolbar Settings button opens (provider / model / skin / language / SFX). Same as /settings.
About new
Small in-panel dialog with version, author, license, repo link, portfolio, and contact phone. Closes on backdrop click, × button, or Esc.
Reload Panel new
Re-reads panel/index.html + panel.js + skins/* with a per-file ?v=<mtime> cache-buster and reassigns panel.webview.html. Picks up CSS/JS edits without rebooting VSCode. The extension host stays alive — terminal, supervisor, chat history all persist.
Reload Window new
Triggers workbench.action.reloadWindow. Use this only when you've edited extension.js (host-side code) and the panel reload isn't enough. It's a full VSCode window reload.

Modals & dialogs ↑ top

Settings modal — provider / model / skin / language / SFX
  • Provider: full dropdown of every direct-API + bridge provider. Picking one switches the active session AND auto-starts the matching bridge exe (if applicable).
  • Model: per-provider list of models (e.g. claude-opus-4-8, claude-sonnet-4-6, claude-haiku-4-5 for Anthropic). The list is refreshed from each provider's live models endpoint once per day (cached; silent-fail to the built-in defaults if the fetch errors), so newly released models show up without an extension update.
  • Skin: visual theme. See Skins.
  • Language: 39 locales available. Switching re-pulls the strings map and re-translates every tooltip / label / help button live.
  • SFX enabled: toggle UI sound effects (clicks, ticks, modal open/close, etc.).
  • SFX volume: 0–100 slider. Previewed live as you drag.
  • Cancel reverts any live previews (SFX/skin) you tried; Save persists and emits setProvider.
Setup wizard — multi-step API key entry

Walk-through for every integration. Each step asks for credentials and writes them to config.ini. Skip moves on without writing; Next writes and advances; final step's Done closes. Steps include: Anthropic, OpenAI, Gemini, xAI/Grok, GitHub PAT, Email/SMTP (Gmail app password), Cloudflare, Twilio, ElevenLabs, Stability AI, Runway, SendGrid, NameSilo, and more.

Accounts modal — multi-account API key manager

For each provider, manage multiple labeled accounts (e.g. "personal", "work"). Switch which one is active per-session without overwriting the others. Keys are masked end-to-end and saved per-provider in config.ini.

Domains modal — NameSilo

Lists every domain on your NameSilo account with nameservers + registration dates. The Reload button forces a fresh API fetch (otherwise it caches in domains.txt).

Handbook modal

Renders a project handbook HTML (intended as a system-prompt reference the model can consult). Configurable per-project.

Stored prompts modal

Insertable prompt templates from stored_prompts/. Each file is one template; filename prefix NN- controls sort order. The "+" button creates a new one.

Chat history modal

Pick a UTC date to load the chat log from chats/<date>.log. Read-only.

Extensions modal

Cards for every installed extension. Pin to toolbar / unpin, install from the public catalog (extensions.xml.php on the server), or remove from disk.

Change log modal

Renders panel/change_log.html — the bundled release notes. Generated via tools/build_changelog.py.

View Source modal

Pretty-prints any code block or the panel's full HTML, with Prism syntax highlighting and a Copy button. Reached via right-click → View Source.

Auto Prompt modal

Configure a prompt string + countdown interval. After every assistant reply the countdown decrements; when it hits zero CBE auto-sends the configured prompt. Toggled on/off via the Auto Prompt toolbar button.

Settings ↑ top

All settings live in one of two places:

  • workspaceState (VSCode-managed, per-workspace) — provider, model, skin, language, sfx enabled/volume, font size.
  • config.ini (extension root, gitignored) — API keys + per-integration credentials.

Settings persist across panel reloads automatically. The Settings modal is the safe way to change anything; editing config.ini directly works too.

Accounts & API keys ↑ top

Skins ↑ top

Visual themes for the whole panel — buttons, modals, code blocks, even font. Pick one in Settings → Skin. Each skin lives in skins/<id>/ with a manifest.xml (declares colors + accent) and a styles.css (overrides CSS variables).

  • codex-black (default) — dark, monospace, neon-cyan accent
  • glassy — frosted-glass surfaces over a soft backdrop
  • tamagotchi — lime-green LCD handheld; auto-shows the pet widget docked in the composer corner
  • office — Word-style cream/blue chrome
  • macos-color-dock / mint-dock — bottom-dock toolbars with glassy icons
  • terminal / arch / kde / gnome / xfce / ubuntu / redhat — Linux desktop themes

Modal colors come from <colors> entries in each skin's manifest and get pushed onto :root as --cbe-modal-* variables so every modal (including this help) renders in-theme.

Edit Skin

Pick a skin in Settings → Appearance, then click Edit Skin to open the skin editor in a large modal. It shows the skin's raw single-file source in a near-full-height monospace editor.

  • Save — writes your changes back to the skin (a timestamped backup is kept) and remounts the skin live.
  • Save as New — prompts for a new name (blank names and illegal filename characters like / \ : * ? " < > | are rejected) and creates a copy, then selects it.
  • Restore Original — discards your edits and restores the shipped original (after a confirm).
  • Close / Esc / backdrop / ✕ — closes the editor. If you have unsaved changes you'll be asked whether to Save, Save as New, Discard changes, or Cancel (stay in the editor).

Extensions ↑ top

CBE supports two flavors of extension, both discovered automatically from the extensions/ directory at activation.

1. Panel extensions .ext bundle

Mini-apps that render an HTML page inside CBE — calculators, emoji pickers, games, dashboards. Each is a folder under extensions/<id>/ with:

  • manifest.xml — id, name, version, author, description, entry HTML, icon (emoji or icon.svg)
  • extension.html (or whatever the manifest's <entry> says) — the actual app

2. Bridge chat extensions .bridge XML

Browser-bridge LLM providers (chat / inference / video gen). Each is a single XML file at extensions/<id>.bridge + a logo PNG at extensions/icons/<id>.png. Author once, drop in, restart — the provider shows up in Settings, the Accounts modal, and the marketplace card grid with its logo.

20 ship in the box (7 enabled + 13 disabled). See Providers & models for the full list and a sample .bridge file.

Marketplace

Click Extensions in the toolbar to browse what's installed, pin to the toolbar, install new ones from the public catalog, or remove from disk. Bridge entries carry a blue bridge badge. Pinned IDs live in extensions/_pinned.json.

Auto-update (push / pull) ↑ top

CBE syncs its source between machines via a WinSCP push + HTTPS pull channel.

Push (admin only)

If [updates] is_admin = true in config.ini, every activation runs a background WinSCP synchronize remote -mirror that pushes the extension folder to /home/trentontompkins.com/cbe on the server. Manual trigger: /push slash command. Excludes per-machine state: data/ (1.74 GB Chrome profiles), bridges/, node_modules/, .git/, logs/, chats/, config.ini, prompt_history.txt, domains.txt, wake.txt.

Pull (every client)

4 seconds after activation, every client fetches https://trentontompkins.com/cbe/manifest.xml.php and MD5-compares per-file against local copies. Only changed/missing files get downloaded over plain HTTPS GET. Excluded paths are NEVER pulled: config.ini, data/, bridges/, extension.js, panel/panel.js, panel/index.html, package.json, build tools — the rationale being that source ships via .vsix and the server's older copy mustn't clobber in-progress dev work.

Hot reload ↑ top

Two reload paths are exposed via the right-click menu:

  • Reload Panel — re-reads panel/index.html + every JS/CSS asset with a per-file ?v=<mtime> cache-buster and reassigns panel.webview.html. Picks up panel.js / skin CSS / dotmatrix edits without rebooting VSCode. The extension host stays alive (your terminal, supervisor, message handlers, chat history all persist).
  • Reload Window — fires workbench.action.reloadWindow. Use only when you've edited extension.js (host-side code) and Reload Panel isn't enough.

Skin CSS edits also auto-apply via the panel's existing skin watcher — no menu click needed.

Troubleshooting ↑ top

"bridge X chat failed: api key empty in config.ini"

The smart_bridge.py daemon was caching an old gating check in memory. Fixed in the C++-exe routing pivot. If you still see it, kill stale daemons:

powershell -Command "Get-CimInstance Win32_Process | Where-Object { $_.CommandLine -like '*smart_bridge.py*' } | ForEach-Object { Stop-Process -Id $_.ProcessId -Force }"
"copilot has no public REST API — use the browser bridge"

Old extension.js was routing bridge chat through the REST router instead of the actual C++ tray exe. Reload Window to pick up the fixed extension.js, then chat will go straight to bin/CBE-Bridge-Copilot.exe.

HTTP 404 model: sonnet-4.6

Outdated short alias in the Claude bridge config. Fixed — full IDs (claude-sonnet-4-6, claude-opus-4-7, claude-haiku-4-5) are now used.

I edited a file but the panel doesn't show the change
  1. If it's panel.js / skins/*.css / index.html → right-click → Reload Panel.
  2. If it's extension.js / bridges_cpp/*.py → right-click → Reload Window.
  3. If you can't reach the menu (e.g. menu itself isn't loaded yet), launch a fresh VSCode instance with an isolated user-data-dir:
    code --user-data-dir="$env:USERPROFILE\.cbe-edh" --extensionDevelopmentPath="C:\Users\moren\Desktop\Codex Black"
STT fails with "not-allowed"

VSCode sandboxes the webview from microphone permission. CBE auto-falls-back to Windows SAPI (System.Speech.Recognition) launched via PowerShell. You may need to grant mic access at the OS level (Settings → Privacy → Microphone).

Bridge exe missing

Trace log shows BRIDGE:MISSING target=<t> expected=<path>. The C++ tray exes live in bin/CBE-Bridge-<Pretty>.exe. If yours don't exist, rebuild from bridges_cpp/ source (MSVC) or pull a fresh .vsix.
